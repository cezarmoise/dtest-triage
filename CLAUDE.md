# dtest triage (keep / review / remove)

Goal: per dtest test function, decide GREEN=keep, YELLOW=second opinion, RED=remove.
Repo: https://github.com/cezarmoise/dtest-triage (this repo, `~/github/dtest-triage`). Run everything from here.

## Paths

- dtest: `~/github/scylla-dtest` (main checkout; read code at `upstream/next`, `git fetch upstream next` first).
- scylla: `~/github/scylladb` (read-only; unit/cluster tests under `test/`).

## Layout

```
scripts/test_results.py   # Jenkins → jenkins/<job>_long.csv (merges new builds, keeps newest 50)
scripts/gen_data.py       # jenkins/*_long.csv + dtest git + gh → data/<module>.json, data/index.json
cache/prs.json            # sha → PR {number,title} | null
jenkins/                  # raw Jenkins CSVs
data/                     # generated, overwritten on refresh
analysis/<module>.json    # LLM analysis (per-file subagent, .claude/skills/analyze/prompt.md)
.claude/skills/analyze/   # /analyze skill (SKILL.md) + subagent prompt (prompt.md, {MODULE} / {TESTS}, "Update mode")
scripts/refresh.sh        # Jenkins CSVs (jobs below) + fetch dtest next / scylla master + gen_data.py
scripts/delta.py          # tests to recheck since each analysis' dtest_rev/scylla_rev; --apply marks DELETED
.claude/skills/weekly/    # /weekly skill: refresh → delta → recheck subagents → commit
groups.json               # test → review group (Jira component, team, reviewers); for opening Jira issues
scripts/groups.py         # validates groups.json, prints tests per team/group
```

Module = dotted path (`cqlsh_tests.cqlsh_copy_tests` → `cqlsh_tests/cqlsh_copy_tests.py`).

## Jenkins data

- Window: newest 50 builds with results per job. Jenkins keeps only ~30 builds, so each refresh merges finished
  builds not yet stored into the CSV (running builds skipped: pipeline stages publish partial results).
- Jobs, name = `jenkins/<name>_long.csv` = key in `stats.by_job`:
  - `dtest-release`, `dtest-release-with-raft` — full dtest runs.
  - `next-dtest-tablets`, `next-dtest-consistent-topology` — gating dtest, stages of `scylla-master/next`
    (filtered by `--stage`). Old `gating-dtest-release-with-{tablets,consistent-topology-changes}` jobs are stale
    since 2026-08-23. Builds that fail before the dtest stages have no results.
- `*_long.csv`: one row per run (build, split, test, status, duration).
- Builds run 4 parallel splits; some tests run twice per build. Skipped runs excluded from stats.
- Plugin RPC (`getExportCSV`) returns 500 via curl, hence REST API.
- Scope: test functions with ≥1 non-skipped run in any job; tests/files gone from `upstream/next` are skipped (e.g. commitlog_test).
  Tests only ever skipped are excluded (e.g. `migration_test.TestTTLWithMigrate.test_big_table_with_ttls`).

## JSON formats (dashboard contract — keep in sync when changing scripts/prompt)

`data/index.json`: sorted module names, `["alternator_stream_tests", "cqlsh_tests.cqlsh_copy_tests", ...]`.

`data/<module>.json` (generated by `gen_data.py`):
```
{"file": "cqlsh_tests/cqlsh_copy_tests.py",    // path in scylla-dtest
 "rev": "<full sha>",                          // scylla-dtest upstream/next the lines/commits refer to
 "tests": [{"class": "TestX", "name": "test_y",
            "lines": [start, end],              // 1-based, inclusive, at rev
            "defined_in": "<path>::<Class>",    // only if inherited from another class/file; lines refer to it
            "stats": STATS,
            "params": {"[param_id]": STATS},    // {} if not parametrized
            "commits": [COMMIT]}],              // function history, newest first
 "file_commits": [COMMIT]}                     // whole-file history, newest first
STATS  = {"runs", "pass_rate" (0-100), "avg_s", "by_job": {"<job>": {"runs", "pass_rate", "avg_s"}}}
COMMIT = {"sha" (full), "date" (YYYY-MM-DD), "author", "subject", "pr": {"number", "title"} | null}
```
Jobs (`by_job` keys): see "Jenkins data". `pr` is null for direct pushes, Cassandra upstream merges and
pytest-port branch PRs. Function history = `git log -L <start>,<end>:file` (ranges from `ast`);
stops at big refactors (e.g. "port to pytest") → analysis finds real origin from file history.

`analysis/<module>.json` (written by the analyze subagents, schema in `.claude/skills/analyze/prompt.md`):
```
{"file": "...", "analyzed_at": "YYYY-MM-DD",
 "scylla_rev": "<short sha>", "dtest_rev": "<full sha>",  // scylla upstream/master, dtest upstream/next checked against
 "tests": {"<Class>::<test>": {                // = data class + "::" + name; may be missing → GRAY
   "description": "...",
   "origin": {"sha", "date", "pr": int | null, "summary"},   // verified origin; overrides data commits' pr
   "commits": {"<sha>": "1-line summary"},     // short or full sha, match by prefix; may include file commits
   "relevance": "...",
   "duplicates": [{"path", "coverage": "full|partial", "note"}],
   "decision": "GREEN|YELLOW|RED|DELETED",
   "reason": "...",                             // mentions issues as "Bug: ..." / "Note: ..."
   "issues": [{"kind": "bug|note", "tag", "ref", "text"}],
   "deleted": {"sha", "date", "pr": int | null, "prev": "GREEN|YELLOW|RED"}}}}  // only if DELETED (delta.py)
```
Tests may be in analysis but not in data: DELETED, or no non-skipped runs in the Jenkins window.
`duplicates.path` is usually `<repo path>::<test>` (scylla `test/...` or a dtest file), sometimes free text
(other repos, several paths). `issues.ref` = file:line, sha, issue link or "". Tags: prompt.md step 7
(enforced by `check_analysis.py` TAGS).

## Dashboard (what it needs to work)

claude.ai artifact, one HTML file, vanilla JS: https://claude.ai/artifact/KWjMv2KZuU8so4B33tfy9e (its source lives in the
artifact, not in this repo). Read-only on this repo; never pushes to it.

Needs:
- The JSON above on `main`. It relies on: module names from `data/index.json`; test key `<Class>::<test>` = data
  `class` + `::` + `name`; decision values `GREEN|YELLOW|RED|DELETED`; issue `kind` `bug|note`. Renaming or
  re-typing any field in the contract, adding a decision value, or changing the key format breaks it; new optional
  fields are ignored. A missing analysis file is fine (tests show as GRAY, counted only in the total).
- A GitHub connector (`Github CoPilot` or `GitHub`) with `get_file_contents`, `list_commits`, `get_commit`, but only for
  whoever clicks **Reload data**. Published artifacts can't fetch raw.githubusercontent.com.
- The artifact's shared database (not reachable from scripts):
  - `cache/meta`: `{sha, syncedAt, syncedBy, modules, mods: {<module>: {n, ver}}, failed: {<module>: reason}, schema}`.
  - `modules/<module>~<ver>~<part>`: copy of data + analysis per module (analysis-only tests included), split under
    256 KB per part; `ver` = first 12 chars of the synced commit.
  - `cache/lock`: lease so one Reload runs at a time.
  - `votes/<module>::<Class>::<test>~<user id>`: one per person per test,
    `{tid, module, class, test, by, decision: GREEN|RED|null (retracted), note, at, llm_decision, history}`.

Data flow:
- Opening the page reads only the database copy. The copy changes only on **Reload data**: compare the latest `main`
  commit with `cache/meta.sha`; if newer, list the commits since and the files each touched (`get_commit`), re-read just
  those modules at that exact sha. No copy, copy `schema` < 2, or > 60 new commits → full rebuild (~230 connector calls,
  a few minutes). So: push, then click Reload data.
- Effective decision: analysis `DELETED` > vote majority (GREEN vs RED; tie → YELLOW) > analysis `decision` > GRAY.
  Votes are only GREEN or RED; voting is disabled on DELETED tests.
- "LLM changed since a vote": the vote's `llm_decision` ≠ current analysis `decision` (older votes without the field
  are skipped).
- Links: scylla-dtest lines at data `rev` (path from `defined_in` when set); `issues.ref` `file.py:N[-M]` → scylla-dtest
  at data `rev`; `duplicates.path` linked only when it parses (`test/...` → scylladb at `scylla_rev`, dtest files →
  scylla-dtest at `rev`), else plain text; origin PR from analysis `origin.pr` over data commits' `pr`.
- Duration filter: `stats.avg_s` (all jobs) in buckets <10s, 10–30s, 30s–1m, 1–2m, 2–5m, >5m, plus "no runs".

## Review groups

`groups.json` (not read by the dashboard): `groups.<g>` = `{component, team, reviewers, note?}`; `component` is a
Jira `Scylla components` value (setting it auto-assigns the SME) or null; `reviewers` = SME assignee + watchers from
Confluence "Scylla components SMEs auto assignment"; `teams` = Atlassian team members (wider pool). Test → group:
first `overrides` fnmatch on `<module>::<Class>::<test>`, else `modules[<module>]`. New module → add it there
(`scripts/groups.py` fails otherwise).

## Jira format (issues for tests)

Mirror the dashboard's test view. Source: `data/<module>.json` + `analysis/<module>.json` at `main` (pull first) and
`groups.json`. Votes live only in the dashboard's database: don't mention them unless the user gives the outcome.

Fields:
- Project `SCYLLADB`; issue type: ask unless given. Labels: `dtest-triage`, `dtest-<decision lowercase>`.
- Group = `groups.json` group of the test (see "Review groups"). `component` set → `Scylla components`
  (customfield_10321) = it, leave assignee empty (auto-assigns the SME). `component` null → assignee = first reviewer.
  Other reviewers → watchers if the tool allows, else the "Review group" line below.
- One issue per test by default. If the user asks to group: one issue per review group, tests as sections.
- Summary: `dtest triage: <module>::<Class>::<test> (<DECISION>)`; grouped:
  `dtest triage: <group>, <N> tests (<x> RED, <y> YELLOW, ...)`.

Description, Markdown (convert if the tool wants wiki markup or ADF). Order as below; omit empty sections, except
Issues ("None found"):
```
**<DECISION>** (LLM, analyzed <analyzed_at>) · <b> bugs · <n> notes · Dashboard: https://claude.ai/artifact/KWjMv2KZuU8so4B33tfy9e
Test: [`<path>:<start>–<end>`](<dtest>/blob/<rev>/<path>#L<start>-L<end>) `<Class>::<test>` (inherited from `<defined_in>`)
Analyzed against scylla [`<scylla_rev>`](<scylla>/commit/<scylla_rev>) and dtest [`<dtest_rev:10>`](<dtest>/commit/<dtest_rev>); test data at dtest `<rev:10>`
Review group: <group> (<team>), reviewers: <names>

#### Deleted                      (only if DELETED)
<date> [`<sha:10>`](<dtest>/commit/<sha>) [#<pr>](<dtest>/pull/<pr>); decision before deletion: <prev>
#### Description
#### Reason
#### Issues
| Kind | Tag | Text | Ref |      bugs first; ref linked per the dashboard rules, else `code`
#### Relevance
#### Duplicates
| Coverage | Path | Note |       path linked only if it parses (dashboard rules), else `code`
#### Origin
<date> [`<sha:10>`](<dtest>/commit/<sha>) [#<pr>](<dtest>/pull/<pr>) (or "no PR"): <summary>
#### Jenkins
<runs> runs, <pass> pass, <avg> average (all jobs combined)
| Job | Runs | Pass | Avg |          from stats.by_job; then | Param | Runs | Pass | Avg | if params
#### Commits
| Date | Commit | PR | Summary |    test commits, newest first
#### File commits
| Date | Commit | PR | Summary |    file_commits the analysis summarized that aren't in the test's commits
```
- `<dtest>` = https://github.com/scylladb/scylla-dtest, `<scylla>` = https://github.com/scylladb/scylladb;
  `<path>` = `defined_in` path if set, else data `file`; `<x:10>` = first 10 chars, links use the full sha.
- Commit rows: Summary = analysis `commits` summary (prefix match) else `subject`, then ` (<author>)`. PR = commit `pr`;
  for the origin commit use `origin.pr` and add "(origin)" after the sha. More than 20 commits → newest 20, then
  "… <N> older, see the dashboard".
- Numbers as on the dashboard: pass rate `100%` / `97.2%`; durations `<60s` → `19s`, else minutes `1.4m`;
  dates `YYYY-MM-DD`; no runs → "No runs recorded".
- Grouped issue: first a table `| Test | Decision | Bugs | Notes | Pass | Avg |`, then per test `### <Class>::<test>`
  with the header lines and `####` sections above.

## Rubric

Single source: `.claude/skills/analyze/prompt.md` steps 3, 6, 7 (agreed 2026-10-20; issues 2026-10-21). Edit there.

## Analysis

Use the `analyze` skill (`/analyze <module>` or `/analyze next`, or "analyze file X" / "analyze next file").
`scripts/pending.py` lists unanalyzed tests in chunks; `scripts/check_analysis.py <module>` validates a result.

Once a week: `/weekly` skill. `scripts/delta.py` (docstring lists what it detects) finds tests to recheck since
each module's `dtest_rev`/`scylla_rev`; rechecks use prompt.md "Update mode".
